# 17 — ย้ายข้อมูลจาก FlowAccount

เอกสารนี้เขียนจากการอ่าน `api-spec.openapi.json` ของ FlowAccount โดยตรง (127 endpoints)
ไม่ใช่จากความจำหรือการเดา

## ข้อเท็จจริงที่กำหนดรูปแบบการย้าย

**Open API ให้เอกสารและข้อมูลหลัก แต่ไม่ให้ GL**

| มีใน API | ไม่มีใน API |
|---|---|
| ผู้ติดต่อ สินค้า หน่วยนับ หมวดสินค้า พนักงาน | สมุดรายวัน |
| ใบเสนอราคา ใบแจ้งหนี้ ใบกำกับภาษี ใบเสร็จ บิลเงินสด | บัญชีแยกประเภท |
| ใบลดหนี้ ใบเพิ่มหนี้ ใบวางบิล | งบทดลอง |
| ใบสั่งซื้อ ใบซื้อ ค่าใช้จ่าย | ผังบัญชี |

มีแค่ `sellChartOfAccountCode` / `buyChartOfAccountCode` ที่ติดมากับบรรทัดสินค้าเท่านั้น

**ผลที่ตามมา:** ย้ายทั้งระบบด้วย API อย่างเดียวไม่ได้ ต้องใช้สองทางประกอบกัน
GL มาจากไฟล์ Excel ที่ส่งออกจากหน้าเว็บ ส่วนบัญชีย่อยมาจาก API

## รายละเอียดทางเทคนิค

```
Production  https://openapi.flowaccount.com/v3-alpha
Sandbox     https://openapi.flowaccount.com/sandbox
Auth        bearer token — client_credentials
            client_id / client_secret จาก MyCompany → connection
Paging      CurrentPage + PageSize
Filter วันที่  StartDate + EndDate (เฉพาะ endpoint ที่เป็นเอกสาร)
```

ค่าคงที่ที่ต้องแปลง — ทั้งหมดอ่านจาก `x-enumNames` ในสเปกจริง

| ฟิลด์ | ค่า |
|---|---|
| `contactType` | 0 = OwnCompany · 3 = Client · 5 = Vendor · 7 = VendorAndClient · 9 = ExpenseVendor |
| `contactGroup` | 1 = Individual · 3 = Juristic · 9 = Undefined |
| `type` (สินค้า) | 1 = Service · 3 = ProductWithNoStock · 5 = ProductWithStock |
| `buyVatType` / `sellVatType` | 1 = Include · 3 = Exclude · 5 = Zero · 7 = None |

## แผนการย้าย — ตัดยอด ไม่ยกทั้งหมด

ห้ามยกใบสำคัญย้อนหลังทุกใบมาลงบัญชีใหม่ เหตุผลสองข้อ

1. เลขที่เอกสารจะชนกับลำดับที่ระบบจองเอง
2. รายการที่ลงบัญชีแล้วในระบบนี้แก้ไม่ได้ ถ้าย้ายผิดต้องกลับรายการทีละใบ

| ขั้น | ข้อมูล | ที่มา | ผลในระบบ |
|---|---|---|---|
| 1 | เลือกวันตัดยอด | — | ควรเป็นวันสิ้นเดือนที่ปิดงบแล้ว |
| 2 | ยอดยกมา | งบทดลอง Excel | ใบสำคัญ `OB` หนึ่งใบ |
| 3 | ลูกหนี้/เจ้าหนี้ค้าง | API | เอกสาร `broughtForward` ไม่ลงบัญชีซ้ำ |
| 4 | ข้อมูลหลัก | API | ทะเบียนคู่ค้า สินค้า |
| 5 | เอกสารที่ปิดแล้ว | — | ไม่ยกมา เก็บไว้ที่ระบบเดิม |

ขั้นที่ 3 สำคัญ — เอกสารค้างยกมาเป็น**บัญชีย่อยเท่านั้น** ยอดของมันอยู่ในงบทดลอง
ขั้นที่ 2 แล้ว ถ้าลงบัญชีซ้ำจะได้ลูกหนี้สองเท่า

## ยอดที่ชำระไปแล้วก่อนวันตัดยอด

เอกสารค้างยกมาอาจชำระมาบางส่วนแล้ว ระบบเก็บยอดนั้นไว้ในฟิลด์ `bfPaid` แยกจาก
`paid` ที่เป็นยอดสะสม เพราะการชำระส่วนนั้นไม่มีใบเสร็จในระบบนี้รองรับ
ถ้าใช้ `paid` ตรง ๆ ในการคำนวณยอดคงค้าง เมื่อรับชำระเพิ่มภายหลังจะถูกหักซ้ำสองครั้ง

```
ยอดคงค้าง ณ วันที่ใด ๆ = total − bfPaid − (ใบเสร็จที่เกิดก่อนวันนั้น)
```

## ข้อควรระวัง

| เรื่อง | ทำอย่างไร |
|---|---|
| FlowAccount ส่งเงินเป็น `number` (ทศนิยมลอยตัว) | ผ่าน `M()` ทุกค่า ห้ามคำนวณต่อจาก float |
| `isVatInclusive: true` | ถอดฐานด้วย `baseFromIncl()` ไม่ใช่คูณ 7% ทับ |
| VAT ไม่ตรง | ตรวจ ฐาน + ภาษี = ยอดรวม ใบไหนไม่ตรงให้ตกเป็นรายการที่ต้องดูเอง ห้ามดัดตัวเลข |
| ภาษีหัก ณ ที่จ่ายบนเอกสารเดิม | ระบบเตือนให้เลือกประเภทเงินได้เองตอนจ่ายชำระ เพราะเปอร์เซ็นต์อย่างเดียวบอกประเภทไม่ได้ |
| เลขที่เอกสารเดิม | เก็บใน `legacyNo` |
| ยอดยกมาไม่มีเอกสารในทะเบียนภาษี | `reconciliationChecks` กันใบสำคัญชนิด `opening` ออกจากการเทียบ VAT ให้แล้ว |
| `/v3-alpha` ยังเป็น alpha | ทดสอบกับ `/sandbox` ให้ผ่านก่อน |

## เกณฑ์ว่าย้ายสำเร็จ

หลังนำเข้า หน้าสรุปจะรัน `reconciliationChecks` ให้ทันที ต้องผ่านครบ 7 ข้อ
โดยเฉพาะสามข้อนี้

- ลูกหนี้รายรายรวม = บัญชีคุมลูกหนี้
- เจ้าหนี้รายรายรวม = บัญชีคุมเจ้าหนี้
- รวมสินทรัพย์ = รวมหนี้สินและส่วนของผู้ถือหุ้น

ข้อไหนไม่ผ่าน แปลว่ายังย้ายไม่ครบ และ `errors.csv` ต้องว่างเปล่า
