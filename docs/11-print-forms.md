# 11 — สเปกแบบฟอร์มพิมพ์

เอกสารที่พิมพ์ออกจากระบบคือหลักฐานทางกฎหมาย ผิดรูปแบบ = ผู้ซื้อใช้เครดิตภาษีซื้อไม่ได้
และผู้ขายอาจถูกประเมินเบี้ยปรับ เอกสารนี้กำหนดสิ่งที่ต้องมีในทุกแบบฟอร์ม

## 0. ข้อกำหนดร่วมทุกแบบฟอร์ม

| หัวข้อ | ข้อกำหนด |
|--------|-----------|
| ขนาดกระดาษ | A4 (210×297 มม.) แนวตั้ง เว้นแนวนอนเฉพาะรายงานที่ระบุ |
| ระยะขอบ | บน 15 · ล่าง 15 · ซ้าย 15 · ขวา 12 มม. (เว้นบน 40 มม. เมื่อใช้กระดาษหัวจดหมาย) |
| ฟอนต์ | Sarabun 14 pt สำหรับเนื้อหา, 16 pt สำหรับชื่อเอกสาร, ตัวเลข tabular |
| ภาษา | ไทยเป็นหลัก มีอังกฤษกำกับได้ (ตั้งค่าต่อคู่ค้าได้) |
| ปี | พ.ศ. เป็นค่าเริ่มต้น (เอกสารที่ยื่นราชการต้องใช้ พ.ศ. เสมอ) |
| ตัวเลขเงิน | คั่นหลักพัน ทศนิยม 2 ตำแหน่งเสมอ ชิดขวา |
| จำนวนเงินเป็นตัวอักษร | บังคับในใบเสร็จรับเงินและใบกำกับภาษี เช่น "(หนึ่งแสนเจ็ดพันบาทถ้วน)" |
| หน้าต่อเนื่อง | ทุกหน้าต้องมี "หน้า X/Y" + เลขที่เอกสาร + ชื่อผู้ซื้อ ซ้ำที่หัวกระดาษ |
| ยอดยกไป/ยกมา | เมื่อรายการเกินหน้า ต้องมี "ยอดยกไป" ท้ายหน้า และ "ยอดยกมา" ต้นหน้าถัดไป |
| เอกสารที่ยกเลิก | พิมพ์ลายน้ำทแยง "ยกเลิก" ทับทั้งหน้า และห้ามพิมพ์ซ้ำโดยไม่มีลายน้ำ |
| QR / บาร์โค้ด | ใส่ได้ในพื้นที่ที่ไม่บังรายการตามกฎหมาย |

### 1.2 กฎการพิมพ์
- **ต้นฉบับ** ให้ผู้ซื้อ 1 ฉบับ · **สำเนา** เก็บไว้ (ระบบต้องพิมพ์คำว่า "ต้นฉบับ"/"สำเนา" ชัดเจน)
- พิมพ์ซ้ำต้นฉบับต้องระบุ **"ใบแทนใบกำกับภาษี"** พร้อมเหตุผลและวันที่ออกใบแทน
- เอกสารที่ออกเป็น e-Tax Invoice: พิมพ์ PDF ที่แสดงเลขที่ใบรับรองและวันเวลาที่ลงลายมือชื่อ

### 1.3 ตัวตรวจสอบก่อน issue (ระบบต้อง block)
```
[ ] เลขประจำตัวผู้เสียภาษีผู้ซื้อ 13 หลัก ผ่าน checksum
[ ] ระบุสาขาทั้งผู้ออกและผู้ซื้อ
[ ] ทุกบรรทัดมีคำบรรยายภาษาไทย
[ ] ยอด VAT = ฐานภาษี × อัตราที่มีผล ณ วันที่เอกสาร (คลาดเคลื่อนได้ ≤ 0.01)
[ ] วันที่เอกสารอยู่ในงวดที่เปิด
[ ] ผู้ซื้อไม่ติดสถานะ credit_hold (ถ้าเป็นการขายเชื่อ)
```

## 2. ใบกำกับภาษีอย่างย่อ — ม.86/6

- ใช้ได้เฉพาะกิจการขายปลีก/ให้บริการรายย่อยที่ได้รับอนุมัติ
- **ไม่ต้อง** ระบุชื่อ-ที่อยู่ผู้ซื้อ
- ต้องมีคำว่า "ใบกำกับภาษีอย่างย่อ"
- ราคาสินค้าที่แสดง **รวม VAT แล้ว** และต้องมีข้อความว่า "ราคารวมภาษีมูลค่าเพิ่มแล้ว"
- **ระบบต้องกันไม่ให้ผู้ซื้อบันทึกเป็นภาษีซื้อที่ขอคืนได้** → ผูก tax_code `VAT7_NC` อัตโนมัติ

## 3. ใบลดหนี้ / ใบเพิ่มหนี้ — ม.86/9, 86/10

เพิ่มจากใบกำกับภาษีปกติ ต้องมี:

| รายการ | หมายเหตุ |
|--------|----------|
| คำว่า "ใบลดหนี้" หรือ "ใบเพิ่มหนี้" เด่นชัด | |
| **เลขที่และวันที่ของใบกำกับภาษีเดิม** | บังคับ ระบบ NOT NULL |
| **เหตุผลของการออก** | ต้องเป็นเหตุที่กฎหมายรับรอง (ดู `docs/12`) |
| มูลค่าที่ถูกต้อง / มูลค่าตามใบเดิม / **ผลต่าง** | ต้องแสดงทั้งสามจำนวน |
| ภาษีมูลค่าเพิ่มของผลต่าง | แยกบรรทัด |

## 4. ใบเสร็จรับเงิน / ใบเสร็จรับเงิน-ใบกำกับภาษี

- คำว่า "ใบเสร็จรับเงิน" (หรือ "ใบเสร็จรับเงิน/ใบกำกับภาษี" เมื่อรวมสองหน้าที่)
- ชื่อ ที่อยู่ เลขประจำตัวผู้เสียภาษีของผู้รับเงิน
- ชื่อผู้จ่ายเงิน จำนวนเงิน วิธีชำระ (เงินสด/โอน/เช็คเลขที่/บัตร)
- **จำนวนเงินเป็นตัวอักษร**
- กรณีลูกค้าหักภาษี ณ ที่จ่าย: แสดงยอดเต็ม − ภาษีหัก ณ ที่จ่าย = ยอดรับสุทธิ
- ลายมือชื่อผู้รับเงิน

## 6. รายงานภาษีขาย / รายงานภาษีซื้อ

แนวนอน A4 คอลัมน์ตามประกาศอธิบดีฯ:

```

ชื่อผู้ประกอบการ ______________  เลขประจำตัวผู้เสียภาษี ____________

┌────┬──────────┬──────────┬────────────────┬──────────────┬────────┬───────────┬─────────┐
```

**กฎที่ระบบต้องบังคับ**
- ลงรายการภายใน **3 วันทำการ** นับแต่วันที่ออก/ได้รับใบกำกับภาษี
- แยกรายงานตาม **สาขา** (บังคับ)
- ใบลดหนี้แสดงเป็นจำนวนติดลบในวงเล็บ พร้อมอ้างเลขที่ใบกำกับเดิม
- ยอดรวมต้องกระทบกับบัญชีภาษีขาย/ภาษีซื้อในบัญชีแยกประเภทพอดี (ระบบตรวจอัตโนมัติ)

รายงานภาษีซื้อใช้โครงเดียวกัน เปลี่ยนเป็น "ชื่อผู้ขายสินค้า/ผู้ให้บริการ"

## 7. รายงานสินค้าและวัตถุดิบ

```
┌────┬──────┬─────────┬──────┬──────┬──────┬──────┬──────┬──────┐
│วันที่│เอกสาร│รายการ    │  รับ  │      │  จ่าย │      │คงเหลือ│      │
│    │      │         │ปริมาณ│มูลค่า│ปริมาณ│มูลค่า│ปริมาณ│มูลค่า│
└────┴──────┴─────────┴──────┴──────┴──────┴──────┴──────┴──────┘
```
แยกตามชนิดสินค้า และต้องลงรายการภายใน 3 วันทำการเช่นกัน

| ข้อกำหนด | รายละเอียด |
|----------|-------------|
| หัวกระดาษ | ชื่อนิติบุคคล + ชื่องบ + "ณ วันที่ …" (งบแสดงฐานะการเงิน) หรือ "สำหรับปีสิ้นสุดวันที่ …" |
| หน่วย | ระบุ "(หน่วย: บาท)" ที่มุมขวาบนของตาราง |
| คอลัมน์ | ปีปัจจุบัน และปีก่อน เคียงกันเสมอ |
| หมายเหตุ | คอลัมน์ "หมายเหตุ" อ้างเลขหมายเหตุประกอบงบการเงิน |
| ลงนาม | กรรมการผู้มีอำนาจตามหนังสือรับรอง + ตราประทับ (ถ้ามี) |
| รายงานผู้สอบบัญชี | แนบเป็นหน้าแรกก่อนงบการเงิน พร้อมชื่อและเลขทะเบียน CPA |
| ผู้ทำบัญชี | ชื่อและเลขทะเบียนผู้ทำบัญชีตาม พ.ร.บ.การบัญชี |

## 9. เอกสารภายใน

| เอกสาร | สาระสำคัญ |
|--------|-----------|
| ใบสำคัญจ่าย (Payment Voucher) | ผู้ขอเบิก ผู้ตรวจสอบ ผู้อนุมัติ ผู้จ่ายเงิน ผู้รับเงิน — 5 ช่องลายเซ็น |
| ใบสำคัญรับ (Receipt Voucher) | อ้างใบเสร็จ/ใบแจ้งหนี้ที่ตัดชำระ |
| ใบสำคัญทั่วไป (Journal Voucher) | คู่บัญชี เหตุผล เอกสารประกอบ ผู้จัดทำ ผู้อนุมัติ |
| ใบเบิกเงินสดย่อย | วงเงิน คงเหลือ ผู้รับผิดชอบ |
| สลิปเงินเดือน | **PDF ต้องใส่รหัสผ่าน** (เลขบัตรประชาชน 6 หลักท้าย หรือรหัสที่พนักงานตั้ง) |
| ใบสั่งซื้อ | เงื่อนไขการส่งมอบ สถานที่ส่ง ผู้อนุมัติตามวงเงิน |

## 10. การนำไปสร้างจริง (Implementation)

```
เทมเพลตเก็บเป็น HTML + CSS Paged Media  →  เรนเดอร์เป็น PDF ด้วย
  headless Chromium (Playwright) หรือ WeasyPrint

เหตุผล: ทีมแก้เทมเพลตได้โดยไม่ต้อง compile, ตัวอย่างบนหน้าจอตรงกับ PDF 100%,
        รองรับฟอนต์ไทยและการตัดคำได้ดีกว่า library แบบ PDF โดยตรง
```

**ต้องทำ**
- ฝังฟอนต์ Sarabun ลงไฟล์ PDF (ห้ามพึ่งฟอนต์ในเครื่องผู้รับ)
- ทดสอบพิมพ์จริงบนเครื่องพิมพ์เลเซอร์ก่อน go-live ทุกแบบฟอร์ม
- เก็บ PDF ที่ออกแล้วลง object storage พร้อม hash — พิมพ์ซ้ำต้องได้ไฟล์เดิม ไม่ใช่เรนเดอร์ใหม่
  (ถ้าเรนเดอร์ใหม่แล้วข้อมูลคู่ค้าเปลี่ยน เอกสารจะไม่ตรงกับที่ส่งลูกค้าไปแล้ว)
