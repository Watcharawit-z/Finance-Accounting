# 06 — Design System และแนวทาง UX

> โจทย์: **"เว็บที่ไม่ดูเหมือน AI ออกแบบ"** — เอกสารนี้แปลงคำนั้นเป็นกฎที่ใช้ตรวจงานได้จริง

---

## 1. อะไรทำให้เว็บ "ดูเป็น AI ออกแบบ" (ห้ามทำ)

| ลักษณะที่ต้องหลีกเลี่ยง | ทำอะไรแทน |
|--------------------------|-----------|
| ไล่สีม่วง–น้ำเงิน (#6366F1 → #8B5CF6) บนปุ่มและ hero | สีเดียวทึบ ใช้สีแบรนด์เป็น accent ไม่เกิน 10% ของพื้นที่จอ |
| Glassmorphism, เงาฟุ้ง ๆ หลายชั้น, blur ทุกการ์ด | เส้นขอบ 1px + เงาบางมาก 1 ชั้น หรือไม่มีเงาเลย |
| การ์ด bento grid ที่ทุกใบมุมโค้ง 24px เท่ากันหมด | radius 6px สม่ำเสมอ, ตารางข้อมูลมุมเกือบตรง |
| อีโมจิเป็นไอคอนฟีเจอร์ (🚀 ⚡ 💡) | ไอคอนเส้น 1.5px ชุดเดียว (Lucide/Phosphor) หรือไอคอนที่วาดเอง |
| Hero ว่างเปล่า + พาดหัวใหญ่ 72px + ปุ่ม 2 ปุ่มกลางจอ | Hero ที่มี **ภาพหน้าจอจริงของผลิตภัณฑ์** อยู่ครึ่งจอ |
| ข้อความการตลาดกลวง "Revolutionize your workflow" | ประโยคเฉพาะเจาะจง "ปิดงบเดือนมกราคมเสร็จวันที่ 5 ก.พ." |
| ฟอนต์ Inter ทุกจุด + น้ำหนักเดียว | คู่ฟอนต์ที่ตั้งใจ + ใช้น้ำหนัก 3–4 ระดับอย่างมีลำดับ |
| Animation เด้ง ๆ ตอน scroll ทุก section | เคลื่อนไหวเฉพาะที่สื่อความหมาย (โหลด, เปลี่ยนสถานะ) 120–160ms |
| ทุกหน้า padding เท่ากันหมด ไม่มีความหนาแน่นต่างกัน | หน้า marketing โปร่ง / หน้าทำงานแน่น (dense) |
| การ์ดสถิติ 4 ใบเรียงกันโดยไม่มีบริบท | ตัวเลข + เทียบงวดก่อน + เส้น sparkline + ลิงก์ไปดูรายละเอียด |

**หลักคิดเดียว:** ซอฟต์แวร์บัญชีคือ *เครื่องมือทำงาน 8 ชั่วโมงต่อวัน* ไม่ใช่ landing page ของสตาร์ตอัป
งานที่ดีจะดู "เงียบ" — คนใช้ไม่สังเกตดีไซน์ แต่หาตัวเลขที่ต้องการเจอใน 3 วินาที

**Ramp** (ตัวเลขการเงินอ่านง่าย), **Bloomberg Terminal** (ความหนาแน่นสูงสุดโดยไม่มั่ว)

## 3. โทเค็นดีไซน์ (Design Tokens)

### 3.1 สี — โครงสร้าง "หมึกบนกระดาษ"

```css
/* Neutral — ฐานของทุกอย่าง (ใช้ 85% ของจอ) */
--ink-900:  #14181F;   /* ข้อความหลัก */
--ink-700:  #3A424E;   /* ข้อความรอง */
--ink-500:  #6B7480;   /* ข้อความช่วย, label */
--ink-300:  #A8B0BA;   /* placeholder, ไอคอนปิดใช้งาน */
--line-200: #E3E7EC;   /* เส้นแบ่ง, ขอบตาราง */
--line-100: #EFF2F5;   /* พื้นแถวสลับ, พื้นหัวตาราง */
--paper:    #FFFFFF;
--canvas:   #F7F8FA;   /* พื้นหลังนอกการ์ด */

/* Brand — น้ำเงินหมึกอมเขียว ไม่ใช่ม่วง ไม่ใช่ฟ้าสด */
--brand-700: #0F3A4D;
--brand-600: #14556F;  /* ปุ่มหลัก */
--brand-500: #1C6F8F;
--brand-100: #E5F0F5;  /* พื้นหลังสถานะ selected */

/* Semantic — ใช้กับตัวเลขและสถานะเท่านั้น ห้ามใช้ตกแต่ง */
--pos-600: #17694A;    /* ยอดบวก, ชำระแล้ว */
--pos-100: #E6F2ED;
--neg-600: #A32B2B;    /* ยอดติดลบ, เกินกำหนด */
--neg-100: #FAEAEA;
--warn-600: #8A5A10;   /* ใกล้ครบกำหนด, รออนุมัติ */
--warn-100: #FBF1DE;
```
**กฎการใช้สี**
1. สีแบรนด์ใช้ได้กับ: ปุ่มหลัก 1 ปุ่มต่อหน้าจอ, ลิงก์, แถบที่กำลังเลือก — เท่านั้น
2. ตัวเลขติดลบใช้สี `--neg-600` **และ** วงเล็บ `(1,234.00)` (คนตาบอดสีต้องอ่านออก)
3. ห้ามใช้ gradient ทุกกรณี ยกเว้นกราฟพื้นที่ (area chart) ที่ไล่ opacity ของสีเดียว
4. ทุกคู่สีข้อความ/พื้นหลังต้องผ่าน WCAG AA (4.5:1) — ตัวเลขในตารางต้องผ่าน 7:1

### 3.2 โหมดมืด
ไม่ใช่การกลับสี — กำหนดชุดใหม่: `--canvas: #0F1216`, `--paper: #171B21`, `--line-200: #262C34`,
`--ink-900: #E8EBEF` และลดความอิ่มของสี semantic ลง ~15%

### 3.3 ตัวอักษร

```css
/* ไทย + ละติน ต้องคู่กันได้สนิท — ค่าจริงอยู่ใน webapp/shell.html (--sans / --num / --print) */
--sans:  "Inter", "Noto Sans Thai Looped", -apple-system, "Segoe UI", "Thonburi", "Leelawadee UI", Tahoma, sans-serif;
--num:   "Inter", "Noto Sans Thai Looped", ...;   /* ตัวเลขเงิน เลขที่เอกสาร รหัสบัญชี เลขผู้เสียภาษี — tabular-nums ทุกจุด */
--mono:  ui-monospace, "SF Mono", Menlo, Consolas, monospace;   /* เหลือใช้แค่ป้ายปุ่มลัด (kbd) */
--print: "Sarabun", "TH Sarabun New", "Noto Sans Thai Looped", sans-serif;   /* เอกสารพิมพ์ A4 */
```
**เลือกแบบนี้เพราะ "น่าเชื่อถือ" ต้องมาก่อน "ทันสมัย"** (เปลี่ยนจาก IBM Plex Sans Thai เมื่อผู้ใช้ขอให้ฟอนต์ดูดีและน่าเชื่อถือขึ้น
— เทียบ 6 คู่บนหน้าจอจริง คือ IBM Plex Sans Thai, IBM Plex Sans Thai Looped, Noto Sans Thai Looped + Inter,
Anuphan + Inter, Noto Sans Thai + Inter, Sarabun + Inter บนหน้าใบกำกับภาษีและแดชบอร์ด ทั้งจอใหญ่และจอโทรศัพท์)
- **ไทยแบบมีหัว (looped)** คือหน้าตาของหนังสือราชการ ใบแจ้งยอดธนาคาร และแบบ ภ.พ./ภ.ง.ด. ที่นักบัญชีเห็นทุกวัน
  อ่านแล้วรู้สึกเป็นเอกสารทางการ ไม่ใช่แอปโซเชียล และหัวของตัวอักษรช่วยแยกตัวที่หน้าตาคล้ายกันตอนตัวเล็กในตารางแน่น ๆ
- **Inter** เป็นมาตรฐานของหน้าจอการเงิน ตัวเลขแบบ tabular หลักตรงกันทุกแถว 0 กับ O และ 1 กับ l แยกกันชัด
  มีแกน optical size (14–32) ตัวเลขใหญ่ในการ์ดสรุปจึงคมเองโดยไม่ต้องตั้งค่า
- Inter ไม่มีอักษรไทย ตัวไทยจึงตกไปที่ Noto Sans Thai Looped เองทุกที่ ไม่ต้องสลับคลาสตามภาษา
  และตัวไทยของ Noto สูงพอดีกับ Inter (ดูจากภาพเทียบ) ไม่ดูเล็กกว่าเหมือนเอา Sarabun มาชนกับ Inter
- **เลขที่เอกสาร/รหัสบัญชี/เลขผู้เสียภาษี ไม่ใช้ฟอนต์พิมพ์ดีดแล้ว** ใช้ Inter ตัวเลขกว้างเท่ากันแทน (คลาส `.mono` เดิม)
  ฟอนต์พิมพ์ดีดทำให้ระบบบัญชีดูเป็นหน้าจอโปรแกรมเมอร์ ส่วนตัวเลขกว้างเท่ากันก็ยังเรียงตรงหลักเหมือนเดิม
- ใช้น้ำหนัก 400 / 500 / 600 / 700 ตามลำดับความสำคัญ ไม่ใช่ "Inter ทุกจุด น้ำหนักเดียว" ตามข้อ 1
- โหลดจาก Google Fonts แบบ `display=swap` ถ้าเครือข่ายบล็อก จะตกไปที่ฟอนต์ระบบ (Thonburi บน Mac, Leelawadee UI บน Windows) ยังอ่านได้ครบ
- **ยอดในการ์ดสรุปต้องเห็นครบทุกหลัก** — `fitNums()` ใน ui-core ลดขนาดตัวอักษรลงทีละ 1px จนยอดที่ยาวที่สุดในแถวพอดีการ์ด
  ทั้งแถวใช้ขนาดเดียวกัน วัดใหม่ทุกครั้งที่วาดหน้า ตอนฟอนต์โหลดเสร็จ และตอนย่อขยายหน้าต่าง (ยอดหลักแสนล้านบนจอ 390px ก็ไม่ล้น — ทดสอบใน uitest)

```
สเกล (ใช้แค่ 7 ขนาด ห้ามเพิ่ม)
11px / 16   label เล็ก, หน่วย, หมายเหตุใต้ฟิลด์
12px / 18   ตารางความหนาแน่นสูง, ข้อความช่วย
13px / 20   ★ ขนาดพื้นฐานของหน้าทำงาน
14px / 22   ข้อความพื้นฐานของหน้า marketing และฟอร์ม
16px / 24   หัวข้อย่อย, ตัวเลขในการ์ดสรุป
20px / 28   หัวข้อหน้า
28px / 36   ตัวเลขเด่น (KPI), พาดหัว marketing
```
**กฎตัวเลข (สำคัญที่สุดในระบบบัญชี)**
```css
.num { font-variant-numeric: tabular-nums; text-align: right; letter-spacing: -0.01em; }
```
- ตัวเลขเงินทุกตัวชิดขวา, ใช้ tabular figures เพื่อให้หลักตรงกัน
- คั่นหลักพันด้วย `,` ทศนิยม 2 ตำแหน่งเสมอ (แม้เป็น .00)
- หน่วยเงิน (`฿` หรือ `THB`) แสดงที่หัวคอลัมน์ ไม่ใช่ทุกแถว
- ยอดรวมใช้น้ำหนัก 600 + เส้นคั่นด้านบน 1px

### 3.4 ระยะห่าง
ฐาน 4px: `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`
- **หน้าทำงาน (app):** padding การ์ด 16px, ความสูงแถวตาราง 34px (compact) / 40px (default)
- **หน้าการตลาด:** ระยะระหว่าง section 96–120px
- ความกว้างเนื้อหาสูงสุด: หน้า marketing 1120px, หน้า app เต็มจอ (ตารางต้องใช้พื้นที่ทุกพิกเซล)

### 3.5 ขอบและเงา
```css
--radius-sm: 4px;   /* input, badge */
--radius-md: 6px;   /* ปุ่ม, การ์ด */
--radius-lg: 8px;   /* modal */
--shadow-1: 0 1px 2px rgba(20,24,31,.06);              /* การ์ด */
--shadow-2: 0 4px 12px rgba(20,24,31,.10);             /* dropdown */
--shadow-3: 0 16px 48px rgba(20,24,31,.16);            /* modal */
```
ไม่มี `--shadow-4` ขึ้นไป ไม่มี glow ไม่มีเงาสี

## 4. โครงหน้าจอแอป

```
┌──────────────────────────────────────────────────────────────────┐
│ แถบบน 48px:  โลโก้ │ เลือกบริษัท ▾ │ งวด: ม.ค. 2569 ▾   ⌘K ค้นหา │ ผู้ใช้ │
├──────────┬───────────────────────────────────────────────────────┤
│ เมนูข้าง  │  หัวข้อหน้า + breadcrumb          [ปุ่มรอง] [ปุ่มหลัก] │
│ 224px    ├───────────────────────────────────────────────────────┤
│ ยุบเหลือ  │  แถบกรอง: ช่วงวันที่ · สถานะ · มิติ · บันทึกมุมมองไว้   │
│ 56px ได้  ├───────────────────────────────────────────────────────┤
│          │                                                       │
│ ภาพรวม   │   ตารางข้อมูล — ตรึงหัวตาราง, ตรึงคอลัมน์แรก,          │
│ ขาย      │   ผลรวมท้ายตารางตรึงล่าง, เลือกหลายแถวได้              │
│ ซื้อ      │                                                       │
│ ธนาคาร   │                                                       │
│ บัญชี    ├───────────────────────────────────────────────────────┤
│ ภาษี     │  แสดง 1–50 จาก 1,284 รายการ    ‹ 1 2 3 ›   รวม ฿12.4M │
│ รายงาน   │                                                       │
└──────────┴───────────────────────────────────────────────────────┘
```

**รายละเอียดที่ทำให้ต่างจากเว็บ AI ทั่วไป**
- **ตัวเลือกงวดบัญชีอยู่บนแถบบนตลอดเวลา** — นักบัญชีคิดเป็น "งวด" ไม่ใช่ "ช่วงวันที่"
- ตารางมี **แถวรวม (footer) ตรึงอยู่ล่างจอ** ไม่ใช่ต้องเลื่อนไปสุด
- คลิกตัวเลขใดก็ได้ → เปิด **แผงข้าง (side panel)** แสดงรายการที่ประกอบเป็นตัวเลขนั้น ไม่ใช่เปลี่ยนหน้า
- แต่ละหน้ามี **มุมมองที่บันทึกไว้** (saved view) เหมือน filter ของ Excel ที่จำได้

## 5. รูปแบบ UI ที่ต้องทำให้ดีเป็นพิเศษ

### 5.1 หน้าคีย์เอกสาร (Document Entry)
- คีย์ได้ทั้งใบด้วยคีย์บอร์ดล้วน: `Tab` ไปฟิลด์ถัดไป, `Enter` เพิ่มบรรทัดใหม่, `Ctrl+S` บันทึก, `Ctrl+Shift+P` ลงบัญชี
- ช่องค้นหาสินค้า/บัญชี พิมพ์รหัสหรือชื่อก็ได้ แสดงผลใน 50ms (index ฝั่ง client)
- ยอดรวม/VAT คำนวณสดที่มุมขวาล่างขณะพิมพ์ ไม่ต้องกดปุ่มคำนวณ
- บันทึกฉบับร่างอัตโนมัติทุก 20 วินาที (เน็ตหลุดไม่เสียงาน)
- ตรวจสอบแบบ inline: เตือนสีเหลืองเมื่อ "ยังไม่แนบใบกำกับภาษี", สีแดงเมื่อ "เลขผู้เสียภาษีไม่ถูกต้อง"

### 5.2 ตารางข้อมูล
- ความหนาแน่น 3 ระดับให้ผู้ใช้เลือก (compact/default/comfortable) จำค่าไว้ต่อผู้ใช้
- คอลัมน์ปรับความกว้าง/ซ่อน/สลับลำดับได้ และจำไว้
- คลิกขวาได้เมนูบริบท (นักบัญชีที่มาจาก Express คุ้นกับสิ่งนี้)
- Export ปุ่มเดียว ได้ Excel ที่มี **สูตรจริงและหัวตารางแช่แข็ง** ไม่ใช่ CSV เปล่า

### 5.3 หน้าเอกสารพิมพ์ (ใบกำกับภาษี/ใบเสร็จ)
- ตัวอย่างพิมพ์ต้องตรงกับกระดาษจริง 100% (A4, ระยะขอบ 15mm)
- รองรับกระดาษหัวจดหมายของบริษัท (เว้นพื้นที่ส่วนหัว)
- พิมพ์ "ต้นฉบับ / สำเนา" ตามข้อกำหนด, ลายน้ำ "ยกเลิก" เมื่อเอกสารถูก void
- ฟอนต์ในเอกสารพิมพ์ต้องเป็นฟอนต์ที่หน่วยราชการอ่านง่าย (Sarabun 14–16pt สำหรับงานพิมพ์)

### 5.4 สถานะ (Status)
ใช้ **ป้ายสีอ่อน + จุดสี + ข้อความ** ไม่ใช่แค่สี:
```
● ฉบับร่าง (เทา)   ● รออนุมัติ (เหลือง)   ● ลงบัญชีแล้ว (น้ำเงิน)
● ชำระแล้ว (เขียว)  ● เกินกำหนด (แดง)     ● ยกเลิก (เทาขีดฆ่า)
```

### 5.5 สถานะว่างและสถานะผิดพลาด
- Empty state บอก "ทำอะไรต่อ" เป็นปุ่ม ไม่ใช่ภาพประกอบน่ารัก ๆ
- Error ต้องบอก **สาเหตุ + วิธีแก้ + ปุ่มไปแก้** เช่น
  *"ลงบัญชีไม่ได้ เพราะงวด ม.ค. 2569 ปิดแล้ว — [ขอปลดล็อกงวด] หรือ [เปลี่ยนวันที่เป็น ก.พ. 2569]"*

## 6. หน้าเว็บการตลาด (Marketing Site)

โครงที่ควรเป็น — **เน้นหลักฐาน ไม่ใช่คำโฆษณา**

1. **Hero:** พาดหัวที่เป็นข้อเท็จจริง + ภาพหน้าจอจริงขนาดใหญ่ (ไม่ใช่ mockup ลอยในอวกาศ)
   > "ระบบบัญชีที่ออกใบกำกับภาษี ยื่น ภ.พ.30 และปิดงบได้ในที่เดียว"
2. **แถบความน่าเชื่อถือ:** โลโก้ลูกค้า / ตัวเลขที่วัดได้ ("ออกใบกำกับภาษีแล้ว 1.2 ล้านใบ")
3. **ปัญหา–ทางแก้ 3 บล็อก:** แต่ละบล็อกมีภาพหน้าจอของฟีเจอร์นั้นจริง ๆ
4. **ตารางความสอดคล้องกับกฎหมายไทย:** ภ.พ.30 ✓ ภ.ง.ด.3/53 ✓ e-Tax ✓ DBD XBRL ✓
   — จุดขายที่ระบบต่างชาติทำไม่ได้ ต้องอยู่หน้าแรก
5. **เสียงจากผู้ใช้:** อ้างชื่อ ตำแหน่ง บริษัทจริง พร้อมตัวเลขผลลัพธ์
6. **ราคา:** ตารางเปรียบเทียบตรงไปตรงมา ไม่มี "ติดต่อฝ่ายขาย" ในแพ็กเกจเล็ก
7. **คำถามที่พบบ่อย:** เรื่องย้ายข้อมูลจากระบบเดิม, ความปลอดภัย, PDPA, การส่งออกข้อมูล
8. **Footer:** ที่อยู่บริษัทจริง เลขทะเบียนนิติบุคคล นโยบายความเป็นส่วนตัว

**สิ่งที่จะทำให้ดูเป็นมืออาชีพจริง:** ใส่ *ตัวเลขจริงในภาพหน้าจอ* (ยอดที่สมจริง ชื่อบริษัทสมมติแบบไทย
เช่น "บจก. ศรีวัฒนาการค้า") ไม่ใช่ "Lorem ipsum" หรือ "Company A"

## 7. การเข้าถึงและรายละเอียดภาษาไทย

- รองรับคีย์บอร์ดล้วน 100% (นักบัญชีไม่ยกมือจากคีย์บอร์ด)
- Focus ring ชัดเจน 2px สีแบรนด์
- รองรับ **พ.ศ. และ ค.ศ.** สลับได้ (ตั้งค่าต่อผู้ใช้) — แบบภาษีต้องใช้ พ.ศ.
- ปฏิทินเริ่มวันจันทร์, แสดงวันหยุดธนาคารไทย
- การเรียงลำดับภาษาไทยต้องถูกตามพจนานุกรม (ใช้ `Intl.Collator('th')` ไม่ใช่ byte order)
- ค้นหาต้องไม่สนวรรณยุกต์/สระผิดเล็กน้อย (normalize ก่อนเทียบ)
- เลขไทย (๑๒๓) เป็นตัวเลือกสำหรับเอกสารบางประเภท
