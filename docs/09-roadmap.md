# 09 — Roadmap และแผนการสร้าง

## หลักคิด
สร้างให้บริษัทตัวเองใช้จริงก่อน (dogfooding) — ถ้าทีมบัญชีของเรายังไม่ยอมทิ้งระบบเดิม
แปลว่ายังขายไม่ได้ **ห้ามเริ่มขายก่อนใช้เองครบ 2 รอบปิดงบปี**

---

## เฟส 0 — เตรียมการ (เดือน 1)

- [ ] สัมภาษณ์ทีมบัญชีของบริษัทเอง: จับเวลาทุกงานที่ทำจริงใน 1 เดือน หา 5 งานที่กินเวลาที่สุด
- [ ] รวบรวมเอกสารจริงทุกแบบที่บริษัทใช้ (ใบกำกับ ใบเสร็จ ใบสำคัญ) เป็นตัวอย่างทดสอบการพิมพ์
- [ ] ตกลงผังบัญชีมาตรฐานกับสมุห์บัญชี + ผู้สอบบัญชี
- [ ] ยืนยันชื่อแบรนด์ + ตรวจเครื่องหมายการค้า + จองโดเมน
- [ ] ตั้งค่า repo, CI/CD, สภาพแวดล้อม dev/staging
- [ ] **ให้ผู้สอบบัญชีรีวิวเอกสารออกแบบชุดนี้** ก่อนเขียนโค้ดบรรทัดแรก

**ผลลัพธ์:** spec ที่ผ่านการตรวจโดยนักบัญชีจริง + baseline เวลาทำงานปัจจุบัน

---

## เฟส 1 — แกนบัญชี + ใช้งานภายใน (เดือน 2–6)

| ส่วน | รายละเอียด |
|------|-----------|
| Platform | tenant/company/branch, ผู้ใช้, RBAC, audit log, การตั้งค่า, เลขที่เอกสาร, ไฟล์แนบ |
| GL | ผังบัญชี, JE, งวดบัญชี, การล็อก, กลับรายการ, รายการซ้ำ, ปิดงวด/ปิดปี |
| AR | ลูกค้า, ใบเสนอราคา, ใบกำกับภาษี, ใบเสร็จ, ใบเพิ่ม/ลดหนี้, aging |
| AP | ผู้ขาย, ตั้งหนี้, จ่ายชำระ, WHT + 50 ทวิ, เงินสดย่อย, aging |
| Banking | บัญชีธนาคาร, นำเข้า statement, กระทบยอด, ทะเบียนเช็ค |
| Tax | รหัสภาษี, รายงานภาษีซื้อ/ขาย, ภ.พ.30, ภ.ง.ด.1/3/53, ปฏิทินภาษี |
| Reporting | งบทดลอง, งบแสดงฐานะการเงิน, งบกำไรขาดทุน, งบกระแสเงินสด, GL detail, สมุดรายวัน |
| นำเข้าข้อมูล | ผังบัญชี, คู่ค้า, ยอดยกมา จาก Excel |

**เกณฑ์ผ่าน:** ทีมบัญชีปิดงบเดือนได้ครบในระบบใหม่ 3 เดือนติดต่อกัน โดยไม่ต้องกลับไปใช้ระบบเดิม

---

## เฟส 2 — ขยายขอบเขต + เตรียมขาย (เดือน 7–13)

- สินค้าคงคลัง + ต้นทุนถัวเฉลี่ย + ตรวจนับ
- สินทรัพย์ถาวร + ค่าเสื่อม (บัญชี/ภาษี)
- เงินเดือน + ประกันสังคม + ภ.ง.ด.1/1ก
- PR/PO/GR + สายอนุมัติ
- e-Tax Invoice & e-Receipt (ผ่าน Service Provider ก่อน)
- e-Withholding Tax
- ภ.ง.ด.51 + เตือนความเสี่ยง 25%, ภ.ง.ด.50 + กระทบยอดบัญชี–ภาษี
- มิติทางบัญชี + โครงการ + งบประมาณ
- หลายสกุลเงิน
- API + webhook, LINE notification
- **หน้าเว็บการตลาด + เอกสารช่วยเหลือ + วิดีโอสอนใช้**

**เกณฑ์ผ่าน:** ลูกค้านำร่อง 3–5 รายใช้งานจริงครบ 1 รอบปิดงบปี รวมถึงยื่นภาษีผ่านระบบทั้งปี

---

## เฟส 3 — Enterprise (เดือน 14–22)

- หลายบริษัท + งบการเงินรวม + รายการระหว่างกัน
- workspace สำหรับสำนักงานบัญชี (จัดการลูกค้าหลายราย)
- DBD e-Filing (XBRL)
- Bank API เชื่อมตรง
- SSO/SAML, MFA บังคับ, IP allowlist
- Report Builder, ตารางส่งรายงานอัตโนมัติ
- Customer Portal
- การผลิต (BOM/ใบสั่งผลิต), Landed cost, Lot/Serial
- ISO 27001 (เริ่มกระบวนการ)

---

## เฟส 4 — AI Layer (เดือน 20 เป็นต้นไป — ทำคู่ขนานกับเฟส 3 ได้)

ลำดับ: แนะนำผังบัญชี → จับคู่ธนาคาร → ตรวจจับความผิดปกติ → OCR →
ถาม-ตอบข้อมูลการเงิน → สรุปผลประกอบการ → พยากรณ์กระแสเงินสด

---

## เฟส 5 — ขยายตลาด (ปีที่ 3+)

- TFRS ฉบับเต็ม (TFRS 15/16/9) สำหรับบริษัทที่โต
- ตลาดอาเซียน: ลาว กัมพูชา เวียดนาม (โครงสร้างภาษีคล้ายกัน — ออกแบบ tax engine ให้ถอดเปลี่ยนได้)
- Marketplace / plugin ให้บุคคลที่สามพัฒนาต่อ

## ความเสี่ยงหลักและการรับมือ

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|-----------|---------|-----------|
| กฎหมายภาษีเปลี่ยน | สูง | Rate-as-data, ติดตามประกาศกรมสรรพากร, มีที่ปรึกษาภาษีประจำ |
| ตัวเลขผิดในระบบบัญชี | **ร้ายแรงที่สุด** | Test ครอบคลุม, reconciliation job รายวัน, ให้ผู้สอบบัญชีตรวจก่อน go-live |
| ทำครบทุกฟีเจอร์แล้วไม่มีอะไรเสร็จ | สูง | ยึดเกณฑ์ผ่านแต่ละเฟสอย่างเคร่งครัด ห้ามข้าม |
| ย้ายข้อมูลจากระบบเดิมยาก | กลาง | ลงทุนกับเครื่องมือนำเข้าข้อมูลตั้งแต่เฟส 1 + ตัวตรวจสอบยอดคุม |
| แข่งกับ FlowAccount/PEAK ที่ราคาถูกกว่า | กลาง | ไม่ชนตลาดล่าง — เน้นบริษัทกลางที่ระบบเหล่านั้นเริ่มไม่พอ |
| e-Tax cert / การรับรองจากกรมสรรพากรใช้เวลานาน | กลาง | เฟสแรกใช้ Service Provider ไปก่อน |
