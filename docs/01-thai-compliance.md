# 01 — กฎหมายและภาษีไทยที่ระบบต้องรองรับ

เอกสารนี้แปลง "ข้อกฎหมาย" เป็น "ข้อกำหนดของระบบ" (System Requirement) โดยตรง
ทุกหัวข้อมีคอลัมน์ *ผลต่อการออกแบบ* ที่นักพัฒนาต้องนำไปทำ

> อ้างอิงข้อมูลสาธารณะ ณ ปี 2569 — ต้องทบทวนกับผู้สอบบัญชี/ที่ปรึกษาภาษีก่อน go-live
> และทบทวนซ้ำทุกปีตามประกาศอธิบดีกรมสรรพากรที่ออกใหม่

---

## 1. พ.ร.บ.การบัญชี พ.ศ. 2543

**สาระที่กระทบระบบ**

| ข้อกำหนด | ผลต่อการออกแบบ |
|----------|-----------------|
| ผู้มีหน้าที่จัดทำบัญชี (ห้างหุ้นส่วนจดทะเบียน, บริษัทจำกัด, บมจ., นิติบุคคลต่างประเทศที่ประกอบธุรกิจในไทย, กิจการร่วมค้า) ต้องจัดทำบัญชีให้ถูกต้องตามมาตรฐานการบัญชี | ตาราง `company` ต้องเก็บ *ประเภทนิติบุคคล* เพื่อกำหนดชุดแบบฟอร์ม/มาตรฐานที่ใช้ |
| ต้องมี **ผู้ทำบัญชี** ที่มีคุณสมบัติตามที่อธิบดีกำหนด และผู้มีหน้าที่จัดทำบัญชีต้องควบคุมดูแล | ระบบต้องมี role `ผู้ทำบัญชี` ผูกกับเลขทะเบียนผู้ทำบัญชี (CPD) และแสดงชื่อบนงบการเงิน |
| ต้องเริ่มทำบัญชีนับแต่วันที่ได้รับจดทะเบียน และปิดบัญชีครั้งแรกภายใน 12 เดือน | `fiscal_year` รองรับรอบบัญชีแรกที่สั้น/ยาวไม่เท่า 12 เดือน |
| **เก็บรักษาบัญชีและเอกสารประกอบการลงบัญชีไม่น้อยกว่า 5 ปี** (สรรพากรอาจกำหนดให้เก็บถึง 7 ปีในบางกรณี) | นโยบาย retention ขั้นต่ำ 5 ปี ตั้งค่าได้ถึง 10 ปี; ห้ามลบเอกสารถาวรก่อนครบกำหนด (soft-delete + legal hold) |
| หากบัญชี/เอกสารสูญหายหรือเสียหาย ต้องแจ้งสารวัตรบัญชีภายใน 15 วัน | มีฟีเจอร์ export ชุดข้อมูลเต็ม + log การเข้าถึงเพื่อใช้ประกอบคำชี้แจง |
| งบการเงินต้องได้รับการตรวจสอบและแสดงความเห็นโดยผู้สอบบัญชีรับอนุญาต (ยกเว้น หจก.ขนาดเล็กตามเกณฑ์) | เก็บข้อมูล CPA ผู้สอบ + เลขทะเบียน + วันที่รายงาน เพื่อพิมพ์บนงบและส่ง DBD |

**ข้อกำหนดระบบที่ตามมา**

- สมุดบัญชีที่ต้องออกได้: สมุดรายวันทั่วไป, รายวันซื้อ, รายวันขาย, รายวันรับเงิน, รายวันจ่ายเงิน,
  บัญชีแยกประเภททั่วไป, บัญชีแยกประเภทย่อย (ลูกหนี้/เจ้าหนี้), งบทดลอง
- เอกสารต้องมีเลขที่เรียงลำดับ ไม่ข้าม ไม่ซ้ำ ต่อประเภทเอกสารต่อบริษัทต่อปี → ใช้ตาราง `document_sequence` ที่ล็อกด้วย DB sequence จริง

## 2. มาตรฐานการรายงานทางการเงิน

### 2.1 TFRS for NPAEs (ปรับปรุง 2565) — ใช้กับ SME ส่วนใหญ่

ประกาศในราชกิจจานุเบกษา 30 พ.ย. 2565 **มีผลบังคับใช้ 1 ม.ค. 2566** ปรับปรุง 17 บท เพิ่มใหม่ 6 บท
เรื่องที่กระทบการออกแบบระบบมากที่สุด:

| หัวข้อ | สิ่งที่ระบบต้องมี |
|--------|-------------------|
| อสังหาริมทรัพย์เพื่อการลงทุน | ประเภททรัพย์สินแยกจาก PP&E, เลือกวิธีราคาทุน |
| เกษตรกรรม / เครื่องมือทางการเงิน / ผลประโยชน์พนักงาน (ทางเลือก) | ผังบัญชีต้องมีกลุ่มบัญชีรองรับ, ตั้งประมาณการหนี้สินผลประโยชน์พนักงาน |
| การรวมธุรกิจ / เงินลงทุนในบริษัทย่อย-ร่วม | โครงสร้าง multi-company + งบรวมในเฟสหลัง |
| การเปลี่ยนแปลงนโยบายบัญชีและการแก้ไขข้อผิดพลาด | ต้องมี "รายการปรับปรุงย้อนหลัง" ที่แยก tag ได้จากรายการปกติ |

### 2.2 TFRS ฉบับเต็ม (PAEs)
เฟส 5 เท่านั้น — ต้องเพิ่ม TFRS 15 (revenue 5 steps), TFRS 16 (สัญญาเช่า), TFRS 9 (ECL)
**ออกแบบเผื่อไว้:** ตาราง `revenue_recognition_schedule` และ `lease_contract` ให้ว่างไว้ก่อน แต่ไม่ต้องทำในเฟส 1

### 2.3 การนำส่งงบการเงิน — DBD e-Filing
- ยื่นงบการเงินภายใน **5 เดือน** นับแต่วันสิ้นรอบบัญชี (รอบปฏิทิน = ภายใน 31 พ.ค.)
- ยื่นผ่านระบบ **DBD e-Filing** รูปแบบ **XBRL** (มี DBD XBRL in Excel v2.0 ให้ 1 ไฟล์ = 1 นิติบุคคล)
- **บอจ.5** (บัญชีรายชื่อผู้ถือหุ้น) นำส่งภายใน 14 วันหลังประชุมผู้ถือหุ้น
- บริษัทจำกัดต้องประชุมสามัญผู้ถือหุ้นอนุมัติงบภายใน 4 เดือนนับแต่วันสิ้นรอบบัญชี

**ผลต่อการออกแบบ:** โมดูล *Statutory Filing* ต้อง export XBRL ตาม taxonomy ของ DBD
และมีปฏิทินเตือน 4 เดือน/5 เดือน/14 วันอัตโนมัติ

## 3. ภาษีมูลค่าเพิ่ม (VAT)

### 3.1 หลักเกณฑ์
- อัตราปัจจุบัน 7% (โครงสร้างกฎหมายคือ 10% แต่ลดโดยพระราชกฤษฎีกาต่อเนื่องรายปี)
  → **ห้าม hardcode 7%** ต้องเก็บใน `tax_rate` ที่มี `effective_from` / `effective_to`
- ผู้ประกอบการที่มีรายรับเกิน 1.8 ล้านบาท/ปี ต้องจดทะเบียน VAT (ภ.พ.01)
- ประเภทรายการที่ต้องแยกให้ได้: VAT 7%, VAT 0% (ส่งออก), ยกเว้น VAT (Exempt),
  นอกขอบข่าย (Out of scope), ภาษีซื้อต้องห้าม (Non-claimable input VAT)

### 3.2 ใบกำกับภาษีเต็มรูป (ม.86/4 ประมวลรัษฎากร)
ต้องมีรายการอย่างน้อย:
1. คำว่า **"ใบกำกับภาษี"** ในที่เห็นเด่นชัด
2. ชื่อ ที่อยู่ และ **เลขประจำตัวผู้เสียภาษีอากร 13 หลัก** ของผู้ออก
3. ชื่อ ที่อยู่ ของผู้ซื้อ/ผู้รับบริการ (และเลขประจำตัวผู้เสียภาษีของผู้ซื้อ ตามประกาศเพิ่มเติม)
4. หมายเลขลำดับของใบกำกับภาษี และเลขลำดับของเล่ม (ถ้ามี)
5. ชื่อ ชนิด ประเภท ปริมาณ และมูลค่าของสินค้า/บริการ
6. จำนวนภาษีมูลค่าเพิ่ม **แยกออกจากมูลค่าสินค้าให้ชัดเจน**
7. วัน เดือน ปี ที่ออกใบกำกับภาษี
8. ระบุ "สำนักงานใหญ่" หรือ "สาขาที่ …" ของทั้งผู้ออกและผู้ซื้อ

**ผลต่อการออกแบบ:** validator ระดับ API — ห้าม issue ใบกำกับภาษีถ้าฟิลด์ข้างต้นไม่ครบ
และต้องเก็บ snapshot ชื่อ/ที่อยู่/เลขผู้เสียภาษีของคู่ค้า ณ วันที่ออก (ไม่ใช่ join สด)

### 3.3 ใบเพิ่มหนี้ / ใบลดหนี้ (ม.86/9, 86/10)
- ออกได้เฉพาะเหตุตามกฎหมาย (สินค้าขาด/เกิน, ลดราคา, รับคืนสินค้า, บอกเลิกสัญญา ฯลฯ)
- ต้องอ้างอิงเลขที่และวันที่ของใบกำกับภาษีเดิม + ระบุ **เหตุผล**
- **ผลต่อการออกแบบ:** ตาราง `credit_note` ต้องมี `original_tax_invoice_id` (NOT NULL) + `reason_code` จาก enum ที่ตรงกฎหมาย

### 3.4 ใบกำกับภาษีอย่างย่อ (ม.86/6)
สำหรับขายปลีก/บริการรายย่อย — ผู้ซื้อ **นำภาษีซื้อไปหักไม่ได้**
ระบบต้องกันไม่ให้บันทึกใบกำกับภาษีอย่างย่อเป็นภาษีซื้อที่ขอคืนได้

### 3.5 รายงานภาษีซื้อ / รายงานภาษีขาย
- รูปแบบตามประกาศอธิบดีฯ: ลำดับ, วันเดือนปีของใบกำกับ, เลขที่ใบกำกับ, ชื่อผู้ขาย/ผู้ซื้อ,
  เลขประจำตัวผู้เสียภาษี, สำนักงานใหญ่/สาขา, มูลค่าสินค้าหรือบริการ, จำนวนภาษี
- ต้องลงรายการภายใน **3 วันทำการ** นับแต่วันที่ได้มา/ออกใบกำกับ
- แยกรายงานตาม **สาขา** ถ้ามีหลายสาขา

### 3.6 การยื่นแบบ ภ.พ.30
- ยื่นรายเดือน **ภายในวันที่ 15** ของเดือนถัดไป (ยื่นออนไลน์ผ่าน rd.go.th ขยายถึงประมาณวันที่ 23)
- ภาษีขาย − ภาษีซื้อ = ชำระเพิ่ม / เครดิตยกไป
- แบบที่เกี่ยวข้องอื่น: **ภ.พ.36** (นำส่ง VAT แทนผู้ประกอบการต่างประเทศ เช่น ค่าบริการจากต่างประเทศ),
  **ภ.พ.01/ภ.พ.09** (จดทะเบียน/เปลี่ยนแปลง)

**ผลต่อการออกแบบ:** เมนู "ปิดภาษีเดือน" ที่ (1) ล็อกงวด (2) สร้างรายงานภาษีซื้อ/ขาย
(3) สร้างชุดตัวเลข ภ.พ.30 (4) สร้าง JE บันทึกภาษีที่ต้องชำระ (5) เก็บไฟล์แนบใบเสร็จรับชำระ

## 4. ภาษีเงินได้หัก ณ ที่จ่าย (Withholding Tax)

### 4.1 แบบที่ต้องรองรับ

| แบบ | ผู้ถูกหัก | ใช้เมื่อ | กำหนดยื่น |
|-----|-----------|----------|-----------|
| ภ.ง.ด.1 | บุคคลธรรมดา — เงินเดือน/ค่าจ้าง (ม.40(1)(2)) | รายเดือน | ภายในวันที่ 7 ของเดือนถัดไป |
| ภ.ง.ด.1ก | สรุปเงินเดือนทั้งปี | รายปี | ภายใน ก.พ. ของปีถัดไป |
| ภ.ง.ด.2 | บุคคลธรรมดา — ดอกเบี้ย เงินปันผล (ม.40(4)) | รายเดือน | วันที่ 7 |
| ภ.ง.ด.3 | **บุคคลธรรมดา** — ค่าบริการ ค่าเช่า วิชาชีพอิสระ รับเหมา | รายเดือน | วันที่ 7 |
| ภ.ง.ด.53 | **นิติบุคคล** — ค่าบริการ ค่าเช่า ค่าขนส่ง โฆษณา | รายเดือน | วันที่ 7 |
| ภ.ง.ด.54 | จ่ายให้ต่างประเทศ (ม.70) | รายเดือน | วันที่ 7 |

> ยื่นออนไลน์ขยายเวลาได้อีก 8 วัน (ประมาณวันที่ 15) ตามมาตรการขยายเวลาที่ต่ออายุเป็นช่วง ๆ

### 4.2 อัตราหลักที่ต้องมีในตารางอัตรา

| ค่าบริการ / ค่าจ้างทำงานให้ | 3% | |
| ค่าวิชาชีพอิสระ (ม.40(6)) | 3% | |
| ค่าเช่าอสังหาริมทรัพย์ | 5% | |
| ค่าโฆษณา | 2% | |
| ค่าขนส่ง (ผู้ประกอบการขนส่งในไทย) | 1% | |
| ค่านายหน้า / ค่าคอมมิชชั่น (ม.40(2)) | 3% (นิติ) / อัตราก้าวหน้า (บุคคล) | |
| เงินปันผล | 10% | |

### 4.3 e-Withholding Tax
- จ่ายเงินผ่านธนาคารที่เข้าร่วม → ธนาคารหักภาษีและนำส่งกรมสรรพากรแทน + ออกหลักฐานอิเล็กทรอนิกส์
- **ไม่ต้องยื่น ภ.ง.ด.3/53 รายเดือน** สำหรับรายการที่ผ่านระบบนี้
- มาตรการลดอัตราเหลือ **1%** สำหรับการจ่ายผ่าน e-WHT ได้รับการต่ออายุถึง **31 ธ.ค. 2570**

**ผลต่อการออกแบบ (สำคัญมาก):**
- ตาราง `wht_transaction` ต้องมีฟิลด์ `remittance_channel` = `manual` | `e_wht`
- ตอนสร้าง ภ.ง.ด.3/53 ต้อง **กรองรายการ e-WHT ออก** ไม่งั้นนำส่งซ้ำ
- อัตราต้อง lookup จากตารางตาม (ประเภทเงินได้ × ประเภทผู้รับ × ช่องทาง × วันที่จ่าย)

### 4.4 หนังสือรับรองการหักภาษี ณ ที่จ่าย (50 ทวิ)
- ต้องออกให้ผู้ถูกหักทันทีที่จ่ายเงิน, ทำ 2 ฉบับ (ฉบับที่ 1 ผู้ถูกหักใช้แนบ, ฉบับที่ 2 เก็บเป็นหลักฐาน)
- ต้องมีเลขที่เรียงลำดับ (เล่มที่/เลขที่)
- รองรับรูปแบบอิเล็กทรอนิกส์ตามที่กรมสรรพากรกำหนด

## 5. e-Tax Invoice & e-Receipt

### 5.1 สองระบบที่ต่างกัน

| ระบบ | เหมาะกับ | วิธีลงนาม | การนำส่ง |
|------|----------|-----------|-----------|
| **e-Tax Invoice by Email** | รายได้ **ไม่เกิน 30 ล้านบาท/ปี** | ประทับรับรองเวลา (Time Stamp) โดย สพธอ. (ETDA) | ส่งเมลถึงผู้ซื้อ + CC `csemail@rd.go.th` |
| **e-Tax Invoice & e-Receipt** | ทุกขนาด (เหมาะกับกลาง-ใหญ่) | **ใบรับรองอิเล็กทรอนิกส์ (Digital Certificate)** + Digital Signature | ส่งไฟล์ **XML** ตามมาตรฐาน ขมธอ. 3-2560 ให้กรมสรรพากร |

### 5.2 ข้อกำหนดทางเทคนิค
- ไฟล์ต้องเป็น **XML** ตามโครงสร้างที่กรมสรรพากรกำหนด (อ้างอิง UN/CEFACT CII)
- ต้องลงลายมือชื่อดิจิทัลด้วยใบรับรองที่ออกโดย CA ที่ได้รับการรับรอง
- ยื่นคำขอด้วยแบบ **บ.อ.01** ผ่านเว็บ etax.rd.go.th
- นำส่งข้อมูลให้กรมสรรพากรภายในวันที่ 15 ของเดือนถัดไป
- **เก็บรักษาอย่างน้อย 5 ปี** ในรูปแบบที่ตรวจสอบความถูกต้องของลายมือชื่อได้

### 5.3 แรงจูงใจทางภาษี
มาตรการหักรายจ่ายค่าลงทุน/ค่าใช้จ่ายระบบ e-Tax **2 เท่า** ได้รับการต่ออายุครอบคลุมปี 2569–2570

**ผลต่อการออกแบบ:**
```
Invoice (สถานะ issued)
   → e-Tax Document Builder (สร้าง XML)
   → Signing Service (HSM/Cert)      ← แยก service, key ห้ามอยู่ใน app server
   → Submission Queue (retry ได้)
   → RD Response (accepted / rejected + error code)
   → เก็บ XML + signature + receipt ลง WORM storage
```
สถานะ e-Tax ต้องแยกจากสถานะเอกสาร: `not_applicable | pending | signed | submitted | accepted | rejected`

## 6. ภาษีเงินได้นิติบุคคล (CIT)

| แบบ | เนื้อหา | กำหนดยื่น |
|-----|---------|-----------|
| **ภ.ง.ด.51** | ภาษีครึ่งรอบระยะเวลาบัญชี จากประมาณการกำไรสุทธิทั้งปี (จ่ายครึ่งหนึ่ง) | ภายใน **2 เดือน** นับแต่วันสุดท้ายของ 6 เดือนแรก |
| **ภ.ง.ด.50** | ภาษีประจำรอบบัญชี พร้อมงบการเงินที่ผู้สอบบัญชีรับรอง | ภายใน **150 วัน** นับแต่วันสิ้นรอบบัญชี |

**กับดักที่ระบบต้องเตือน:** ถ้าประมาณการกำไรสุทธิใน ภ.ง.ด.51 **ขาดไปเกิน 25%** ของกำไรสุทธิจริง
โดยไม่มีเหตุอันสมควร ต้องเสีย **เงินเพิ่ม 20%** ของภาษีที่ชำระขาด
→ ระบบต้องคำนวณ "ความเสี่ยง 25%" ให้ดูตอนกรอกประมาณการ และเตือนซ้ำเมื่อผลจริงเริ่มเบี่ยง

**อัตราภาษีที่ต้องมีในตาราง (SME ที่เข้าเงื่อนไข ทุนจดทะเบียนชำระแล้ว ≤ 5 ลบ. และรายได้ ≤ 30 ลบ.):**
- กำไรสุทธิ 0–300,000 → ยกเว้น
- 300,001–3,000,000 → 15%
- เกิน 3,000,000 → 20%
- นิติบุคคลทั่วไป → 20%

**การกระทบยอดบัญชี–ภาษี:** ระบบต้องมี worksheet บวกกลับ/หักออก (รายจ่ายต้องห้าม ม.65 ตรี,
ค่าเสื่อมราคาทางภาษี vs ทางบัญชี, ผลขาดทุนสะสมยกมาไม่เกิน 5 รอบบัญชี)

## 7. เงินเดือน ประกันสังคม และแรงงาน

### 7.1 ประกันสังคม (ม.33)
- นายจ้างและลูกจ้างจ่ายฝ่ายละ **5%** ของค่าจ้าง
- **เพดานค่าจ้างใหม่ปี 2569 = 17,500 บาท** → สมทบสูงสุด **875 บาท/เดือน/ฝ่าย** (เดิม 750 บาท)
  โดยแบ่งเป็น เจ็บป่วย/ทุพพลภาพ/ตาย 1.5%, ว่างงาน 0.5%, ชราภาพ+สงเคราะห์บุตร 3%
- ปรับเพดานเป็นระยะ (ระยะที่ 1 ปี 2569–2571) → **ต้องเก็บเพดานเป็นข้อมูลตามช่วงเวลา**
- นำส่งแบบ **สปส.1-10** ภายในวันที่ 15 ของเดือนถัดไป
- **กองทุนเงินทดแทน** — นายจ้างจ่ายฝ่ายเดียว ตามอัตราความเสี่ยงของประเภทกิจการ (0.2%–1.0%) รายปี

### 7.2 อื่น ๆ
- กองทุนสำรองเลี้ยงชีพ (Provident Fund) — หักลูกจ้าง + สมทบนายจ้าง ตามอัตราที่ตกลง
- ค่าจ้างขั้นต่ำตามประกาศคณะกรรมการค่าจ้าง (ต่างกันตามจังหวัด)
- ค่าล่วงเวลาตาม พ.ร.บ.คุ้มครองแรงงาน (OT 1.5 เท่า, วันหยุด 2 เท่า, OT วันหยุด 3 เท่า)
- ค่าชดเชยเลิกจ้างตามอายุงาน (30/90/180/240/300/400 วัน)

## 9. PDPA — พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562

ข้อมูลที่ระบบบัญชีถือครองซึ่งเป็นข้อมูลส่วนบุคคล: ชื่อ-ที่อยู่ลูกค้าบุคคลธรรมดา,
เลขบัตรประชาชน 13 หลัก, เงินเดือนพนักงาน, เลขบัญชีธนาคาร

| หลักการ | ผลต่อการออกแบบ |
|---------|-----------------|
| ฐานทางกฎหมาย | ส่วนใหญ่ใช้ฐาน "หน้าที่ตามกฎหมาย" และ "สัญญา" — ต้องบันทึกฐานที่ใช้ต่อประเภทข้อมูล |
| สิทธิเจ้าของข้อมูล (เข้าถึง/แก้ไข/ลบ/คัดค้าน) | ต้องมี API export ข้อมูลรายบุคคล + flow ขอลบ ที่ **ชนกับหน้าที่เก็บ 5 ปี** → ระบบต้องรองรับ "ปฏิเสธคำขอลบโดยอ้างหน้าที่ตามกฎหมาย" และบันทึกเหตุผล |
| ความปลอดภัย | เข้ารหัสข้อมูลอ่อนไหวระดับคอลัมน์ (เลขบัตร ปชช., เลขบัญชีธนาคาร, เงินเดือน) |
| บันทึกรายการประมวลผล (RoPA) | ต้องมีเอกสาร RoPA ของระบบ ให้ลูกค้า SaaS ใช้อ้างอิงได้ |
| ผู้ประมวลผลข้อมูล | ถ้าขายเป็น SaaS = เราเป็น Data Processor → ต้องมี **DPA** แนบสัญญา |
| แจ้งเหตุละเมิด | แจ้ง สคส. ภายใน **72 ชั่วโมง** → ต้องมี incident runbook + log ที่สืบย้อนได้ |

## 11. หลักการออกแบบเชิงกฎหมายที่ต้องบังคับในโค้ด

1. **Rate-as-data** — ทุกอัตรา (VAT, WHT, SSO, CIT) อยู่ในตารางที่มีช่วงวันที่ ไม่มี magic number ในโค้ด
2. **Period lock** — เมื่อยื่นภาษีงวดใดแล้ว ห้ามแก้เอกสารในงวดนั้น ต้องออกใบเพิ่ม/ลดหนี้ หรือปรับปรุงในงวดถัดไป
3. **Immutable numbering** — เลขที่เอกสารที่ออกแล้ว ยกเลิกได้ (void) แต่ห้ามนำเลขกลับมาใช้ซ้ำ
4. **Snapshot ข้อมูลคู่ค้า** — ชื่อ/ที่อยู่/เลขผู้เสียภาษี/สาขา เก็บติดกับเอกสาร ไม่ผูกแบบ live reference
5. **Attachment เป็นข้อบังคับ** — ประเภทเอกสารที่กฎหมายต้องมีหลักฐาน (ภาษีซื้อ, ค่าใช้จ่าย) ต้องแนบไฟล์ก่อน post ได้
6. **Audit trail แบบ append-only** — ใครแก้อะไร เมื่อไหร่ ค่าเดิม–ค่าใหม่ เก็บแยก DB/partition ที่ลบไม่ได้
