# 08 — AI Layer (ทำทีหลัง แต่ต้องเตรียมตั้งแต่วันนี้)

> ข้อตกลง: **ไม่สร้าง AI ในเฟส 1–3** แต่โครงสร้างข้อมูลต้องรองรับ เพื่อไม่ต้องรื้อระบบภายหลัง

## 1. สิ่งที่ต้องทำ "ตั้งแต่วันนี้" เพื่อให้ AI ใช้งานได้ในเฟสหลัง

| เตรียมอะไร | ทำไม |
|-------------|------|
| **Audit event log ครบทุกการกระทำ** | เป็นข้อมูลฝึกและบริบทของ AI ทั้งหมด ถ้าไม่เก็บตั้งแต่แรกจะย้อนไม่ได้ |
| **ทุกเอกสารมี `source_doc_type` + `source_doc_id` ผูกกับ JE** | AI ต้องอธิบายที่มาของตัวเลขได้ ไม่งั้นตอบแล้วพิสูจน์ไม่ได้ |
| **มิติ (dimensions) บันทึกอย่างมีวินัย** | การวิเคราะห์เชิงลึกทั้งหมดขึ้นกับมิติ ถ้าปล่อยว่างไว้ AI ก็วิเคราะห์อะไรไม่ได้ |
| **ผังบัญชีมี `sub_type` มาตรฐาน** | AI เทียบข้ามบริษัทได้ แม้ลูกค้าตั้งรหัสบัญชีต่างกัน |
| **ผู้ใช้ระบุเหตุผลเวลาแก้/กลับรายการ** | เป็น label ชั้นดีสำหรับสอนโมเดลตรวจจับข้อผิดพลาด |
| **เก็บ text ต้นฉบับจากเอกสาร (memo, description)** | เป็นวัตถุดิบของการจัดหมวดหมู่อัตโนมัติ |
| **ตาราง `gl_balance_monthly` ที่ถูกต้องเสมอ** | AI ถามยอดย้อนหลังได้เร็วโดยไม่ต้อง scan ตารางหลัก |

## 2. สถาปัตยกรรมที่ตั้งใจไว้

```
                    ┌─────────────────────────────┐
ผู้ใช้ถามภาษาไทย  →  │  AI Orchestrator (LLM)      │
                    │  - จำกัด scope ที่บริษัทเดียว │
                    │  - สิทธิ์ = สิทธิ์ของผู้ใช้     │
                    └──────────┬──────────────────┘
                               │ เรียกผ่าน "เครื่องมือ" ที่กำหนดไว้เท่านั้น
        ┌──────────────┬───────┴────────┬──────────────────┐
   get_balance     query_ledger    run_report      detect_anomaly
   (อ่านอย่างเดียว) (SQL ที่จำกัด)  (รายงานที่มีอยู่)  (โมเดลสถิติ)
        └──────────────┴────────────────┴──────────────────┘
                               │
                    Read replica ของ PostgreSQL (ห้ามเขียน)
```

**กฎเหล็ก 5 ข้อของ AI ในระบบบัญชี**
1. **AI อ่านอย่างเดียว** — ห้ามสร้าง/แก้/ลงบัญชีเอง ทำได้แค่ "เสนอร่าง" ให้คนกดยืนยัน
2. **ทุกคำตอบต้องมีที่มา** — แนบลิงก์ไปยัง JE/เอกสารที่ใช้คำนวณเสมอ ถ้าอ้างที่มาไม่ได้ = ไม่ตอบ
3. **สิทธิ์ของ AI = สิทธิ์ของผู้ถาม** — ถามเรื่องเงินเดือนโดยไม่มีสิทธิ์ HR ต้องไม่ได้คำตอบ
4. **ไม่ส่งข้อมูลดิบออกนอกระบบโดยไม่บอก** — ถ้าใช้ LLM ภายนอก ต้องแจ้งลูกค้าใน DPA และให้ปิดได้
5. **ตัวเลขไม่ให้ LLM คำนวณ** — LLM เลือกว่าจะเรียก tool ไหน แต่ตัวเลขมาจาก SQL/โค้ดเสมอ

## 3. ฟีเจอร์ AI เรียงตามความคุ้มค่า

### กลุ่มที่ 1 — คุ้มที่สุด ทำก่อน (ไม่ต้องใช้ LLM ก็ได้)
| ฟีเจอร์ | วิธี | ผลลัพธ์ |
|---------|------|---------|
| **แนะนำผังบัญชีอัตโนมัติ** | ML classifier จากประวัติการลงบัญชีของบริษัทเอง (description + vendor → account) | ลดเวลาคีย์ 40–60% |
| **จับคู่รายการธนาคาร** | Fuzzy matching + learning จากการจับคู่ที่ผู้ใช้ยืนยัน | กระทบยอดเหลือครึ่งเวลา |
| **ตรวจจับใบกำกับซ้ำ** | Hash (vendor_tax_id + doc_no + amount + date) + fuzzy | กันจ่ายซ้ำ |
| **ตรวจจับความผิดปกติของยอด** | สถิติ (z-score, seasonal decomposition) ต่อบัญชี×เดือน | จับค่าใช้จ่ายกระโดดก่อนปิดงบ |

### กลุ่มที่ 2 — ต้องใช้ LLM
| ฟีเจอร์ | รายละเอียด |
|---------|------------|
| **ถาม-ตอบข้อมูลการเงิน** | "กำไรขั้นต้นไตรมาส 1 เทียบปีที่แล้วเป็นยังไง" → เรียก tool → ตอบพร้อมตารางและลิงก์ |
| **สรุปผลประกอบการรายเดือน** | เขียนบทวิเคราะห์ 1 หน้า: อะไรเปลี่ยน ทำไม ควรดูอะไรต่อ |
| **อ่านเอกสาร (OCR + สกัดข้อมูล)** | ถ่ายรูปใบเสร็จ → ได้ร่างรายการพร้อมเลขผู้เสียภาษี ยอด VAT (ผู้ใช้ยืนยันก่อนเสมอ) |
| **ตรวจสุขภาพภาษีก่อนยื่น** | ตรวจ 30+ รายการ: ภาษีซื้อต้องห้าม, ใบกำกับไม่ครบองค์ประกอบ, WHT ที่ลืมหัก, ยอด ภ.พ.30 ไม่ตรง GL |
| **ผู้ช่วยปิดงบ** | ไล่ checklist, ชี้รายการค้าง, เสนอรายการปรับปรุงที่ควรตั้ง |

### กลุ่มที่ 3 — พยากรณ์
| ฟีเจอร์ | วิธี |
|---------|------|
| **พยากรณ์กระแสเงินสด 13 สัปดาห์** | AR/AP ที่ครบกำหนด + พฤติกรรมการจ่ายจริงของลูกค้าแต่ละราย + รายการประจำ |
| **ทำนายวันที่ลูกค้าจะจ่ายจริง** | Survival model จากประวัติ (ลูกค้ารายนี้จ่ายช้ากว่ากำหนดเฉลี่ย 12 วัน) |
| **ประเมินความเสี่ยงหนี้สูญ** | Scoring จากอายุหนี้ + ประวัติ + ขนาดหนี้ |
| **ประมาณการภาษีที่ต้องจ่ายทั้งปี** | จากผลจริง + แนวโน้ม → เตือนก่อนยื่น ภ.ง.ด.51 (กันโดนเงินเพิ่ม 20%) |

## 4. เรื่องที่ต้องระวังเป็นพิเศษ

| ความเสี่ยง | การจัดการ |
|-----------|-----------|
| AI ตอบตัวเลขผิดแล้วผู้บริหารใช้ตัดสินใจ | บังคับแสดงที่มา + ป้าย "ตัวเลขจากระบบ ณ วันที่/เวลา" + ปุ่มไปดูรายละเอียด |
| ข้อมูลการเงินรั่วผ่าน LLM ภายนอก | ตัวเลือกใช้โมเดลที่โฮสต์ในไทย/ในองค์กร, ปิดการเรียนรู้จากข้อมูลลูกค้า, ปิดฟีเจอร์ได้ทั้งหมด |
| Prompt injection ผ่านข้อความในเอกสาร (เช่น memo ที่ผู้อื่นพิมพ์) | ถือข้อความจากเอกสารเป็น "ข้อมูล" ไม่ใช่ "คำสั่ง", แยก context, ไม่ให้ AI ทำ action ใด ๆ |
| ความรับผิดทางวิชาชีพ | ระบุชัดว่า AI เป็นเครื่องมือช่วย ไม่ใช่คำแนะนำทางบัญชี/ภาษี ผู้ทำบัญชียังรับผิดชอบตามกฎหมาย |
| ต้นทุนต่อการเรียก | Cache คำถามที่ซ้ำ, ใช้โมเดลเล็กสำหรับงานจัดหมวดหมู่, โมเดลใหญ่เฉพาะงานวิเคราะห์ |

## 5. ตัวชี้วัดที่ต้องวัดเมื่อเปิด AI

- % ของรายการที่ AI แนะนำบัญชีถูกต้อง (ผู้ใช้กดยอมรับโดยไม่แก้)
- % ของรายการธนาคารที่จับคู่อัตโนมัติสำเร็จ
- จำนวนความผิดปกติที่ AI จับได้ และเป็น "ของจริง" (precision)
- เวลาที่ประหยัดได้ต่อการปิดงบหนึ่งเดือน
- อัตราการถูกแก้คำตอบของผู้ช่วย Q&A (ถ้าสูง = ยังใช้ไม่ได้)
