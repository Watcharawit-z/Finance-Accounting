## 2. ปัญหาที่แก้ (Problem)

ธุรกิจไทยขนาดกลาง (รายได้ 20–500 ลบ./ปี) ติดอยู่ระหว่าง 2 ทางเลือกที่ไม่ดีทั้งคู่

1. **โปรแกรมบัญชีไทยรุ่นเก่า** (Express, ระบบ on-premise) — ถูกกฎหมายไทย แต่ UI ยุค 2005,
   ไม่มี API, ทำงานร่วมกันหลายคนยาก, ไม่มี audit trail ที่ตรวจสอบได้จริง
2. **ระบบสากล** (Xero, QuickBooks, NetSuite) — UX ดี แต่ไม่รองรับ ภ.พ.30 / ภ.ง.ด.3/53 /
   หนังสือรับรองหัก ณ ที่จ่าย / e-Tax Invoice / DBD e-Filing ต้องทำงานคู่กับ Excel ตลอด

ผลคือ: ทีมบัญชีทำงานซ้ำซ้อน 30–50% ของเวลา, ปิดงบช้า 20–45 วัน, ผู้บริหารเห็นตัวเลขช้าเกินไปที่จะตัดสินใจ

## 3. คำสัญญาของผลิตภัณฑ์ (Value Proposition)

|-------|-----------|
| เจ้าของ / CFO | เห็นกระแสเงินสด กำไรรายโครงการ และภาระภาษีล่วงหน้า แบบ near real-time |

## 4. กลุ่มลูกค้าเป้าหมาย (ICP)

- **Primary:** บริษัทจำกัดไทย จด VAT, พนักงาน 20–200 คน, มีทีมบัญชีใน 1–5 คน
  อุตสาหกรรม: เทรดดิ้ง/นำเข้า-ส่งออก, รับเหมา/โครงการ, บริการมืออาชีพ, ผลิตขนาดเล็ก
- **Secondary:** สำนักงานบัญชี (Accounting Firm) ที่ดูแลลูกค้า 20–300 ราย — ต้องการ multi-company workspace
- **ไม่ใช่เป้าหมายตอนนี้:** ร้านค้ารายย่อย/ฟรีแลนซ์ (ตลาด FlowAccount ครองอยู่ ราคาต่ำ),
  บริษัทมหาชนที่ต้องใช้ TFRS เต็มรูป + consolidation ซับซ้อน (เฟส 5 ขึ้นไป)

## 6. ตัวชี้วัดความสำเร็จ (ใช้ภายในก่อน)

- ระยะเวลาปิดงบเดือน ≤ 5 วันทำการ (จากเดิม X วัน — ต้องวัด baseline ก่อนเริ่ม)
- ยอด "รายการที่ยังไม่กระทบยอดธนาคาร" ที่เกิน 30 วัน = 0
- ยื่นแบบภาษีตรงเวลา 100% ไม่มีเบี้ยปรับเงินเพิ่ม
- % ของใบกำกับภาษีที่ออกผ่านระบบ (ไม่ใช่ Word/Excel) ≥ 98%

## 7. หลักการออกแบบที่ห้ามละเมิด (Design Tenets)

1. **ไม่มีการแก้ตัวเลขย้อนหลังแบบเงียบ ๆ** — เอกสารที่ลงบัญชีแล้วต้องกลับรายการ (reverse) เท่านั้น
2. **ทุกยอดคลิกลึกได้ถึงเอกสารต้นทาง** — Report → GL → Journal → Document → ไฟล์แนบ
3. **กฎภาษีเป็นข้อมูล ไม่ใช่โค้ด** — อัตรา VAT/WHT/ประกันสังคม เก็บในตารางที่มีวันเริ่ม–สิ้นสุด
4. **ภาษาไทยเป็นพลเมืองชั้นหนึ่ง** — เลขไทย/พ.ศ./ค.ศ., ชื่อบัญชีไทย-อังกฤษคู่กัน, พิมพ์เอกสารตรงตามแบบราชการ
5. **ออฟไลน์ได้บางส่วน** — ออกใบกำกับภาษีต้องไม่ล่มเพราะเน็ตหลุด (คิวส่งภายหลัง)
