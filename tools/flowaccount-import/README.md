# ตัวย้ายข้อมูลจาก FlowAccount

ดึงข้อมูลจาก FlowAccount Open API แล้วแปลงเป็นแฟ้มที่หน้า **นำเข้าข้อมูลจากระบบเดิม**
ของระบบอ่านได้ ไม่ต้องติดตั้งอะไรเพิ่ม ใช้ Node.js 22+ อย่างเดียว

## 3 ขั้นตอน

```bash
cp tools/flowaccount-import/config.example.json config.json
# แก้ clientId / clientSecret ที่ได้จาก FlowAccount → MyCompany → connection

node tools/flowaccount-import/pull.js    --config config.json --from 2026-01-01 --to 2026-07-31
node tools/flowaccount-import/convert.js --cutoff 2026-07-31 --tb งบทดลอง.csv
# ได้ out/financii-import.json → ลากไปวางที่หน้า "นำเข้าข้อมูลจากระบบเดิม" ในเว็บ
```

แยกขั้น `pull` กับ `convert` ไว้เพื่อให้แปลงซ้ำได้โดยไม่ต้องยิง API ใหม่ทุกครั้ง
ข้อมูลดิบเก็บไว้ที่ `out/raw/` ตรวจย้อนได้ตลอด

## สิ่งที่ API ให้ และสิ่งที่ต้องเอามาเอง

`pull.js` ดึงครบทุกชุดที่ Open API เปิดให้ — ผู้ติดต่อ สินค้า พนักงาน ใบกำกับภาษี
ใบแจ้งหนี้ ใบเสร็จ บิลเงินสด ใบลดหนี้ ใบเพิ่มหนี้ ใบซื้อ และค่าใช้จ่าย

**แต่ Open API ไม่มี GL** — ไม่มีสมุดรายวัน บัญชีแยกประเภท งบทดลอง หรือผังบัญชี
ตรวจแล้วจาก `api-spec.openapi.json` ทั้ง 127 endpoints ไม่มีสักตัว
ส่วนนั้นต้องส่งออกเป็นไฟล์จากหน้าเว็บ FlowAccount เอง

| ต้องการ | เอามาจาก |
|---|---|
| งบทดลอง ณ วันตัดยอด | รายงานด้านบัญชี → งบทดลอง → เลือกรอบระยะเวลา → ดาวน์โหลด Excel |
| ผังบัญชี | บริหารบัญชี → ผังบัญชี → เพิ่มเติม → ดาวน์โหลด Excel |

ไฟล์ `.xlsx` ลากเข้าหน้าเว็บได้ตรง ๆ ส่วน `convert.js --tb` รับเฉพาะ CSV
(เปิดใน Excel แล้ว Save As เป็น CSV)

## หลักที่ยึด

- **ไม่คำนวณ VAT ใหม่เอง** — ใช้ตัวเลขที่ FlowAccount ส่งมา แล้ว*ตรวจ*ว่า
  ฐาน + ภาษี = ยอดรวม จริง ใบไหนไม่ตรงจะตกลง `errors.csv` ไม่ถูกดัดตัวเลขให้ลงล็อก
- **ราคารวมภาษี** (`isVatInclusive`) ถอดฐานด้วย `baseFromIncl()` ตัวเดียวกับที่ระบบใช้
  ไม่ใช่คูณ 7% ทับเข้าไป
- **เงินเป็นจำนวนเต็มสเกล 4 ตลอดทาง** — โหลดคณิตศาสตร์เงินจาก `webapp/src/engine.js`
  ตรง ๆ ไม่เขียนใหม่ จึงไม่มีทางเพี้ยนคนละทางกับตัวระบบ
- **เลขที่เอกสารเดิมเก็บใน `legacyNo`** ไม่เอามาเป็นเลขที่ในระบบใหม่
  เพราะระบบเราจองเลขเองตอนลงบัญชี
- **ตัดยอด ไม่ยกทั้งหมด** — ยกมาเฉพาะใบที่ยัง*ค้าง* ณ วันตัดยอด
  เอกสารที่ปิดแล้วเก็บไว้ที่ FlowAccount ตามเดิม
- **ใบลดหนี้หัก ใบเพิ่มหนี้บวก** — ใบลดหนี้ก่อนวันตัดยอดถูกหักออกจากใบกำกับที่ยังค้าง
  ส่วนใบเพิ่มหนี้ที่ยังเก็บเงินไม่ได้ถูกยกมาเป็นลูกหนี้ค้างของตัวเอง
  ทั้งสองทางต้องทำ ไม่งั้นยอดลูกหนี้จะเกินหรือขาดไปเงียบ ๆ

## ไฟล์ที่ได้

| ไฟล์ | เนื้อหา |
|---|---|
| `out/raw/*.json` | ข้อมูลดิบจาก API ไม่ผ่านการแปลง |
| `out/financii-import.json` | แฟ้ม `financii-import/1` สำหรับลากเข้าเว็บ |
| `out/errors.csv` | ทุกรายการที่แปลงไม่ได้ พร้อมเหตุผล |

| `out/coverage.csv` | ทุกแถวที่อ่านมา ไปอยู่ไหนบ้าง — ยกมา ปิดแล้ว ซ้ำ หรือแปลงไม่ได้ |

`errors.csv` ว่างเปล่าเท่านั้นจึงถือว่าย้ายครบ ถ้ามีบรรทัดต้องตามแก้ที่ต้นทางก่อน

## สามด่านที่กันข้อมูลหาย

1. **ตัดเอกสารเลขซ้ำข้ามชุดข้อมูล** — ใบเดียวกันโผล่ได้ทั้งใน `receivable-invoices`
   และ `tax-invoices` ถ้ารวมทั้งสองรายการ ยอดลูกหนี้จะถูกนับซ้ำสองเท่า
2. **รายงานความครบถ้วน** — ทุกแถวที่อ่านมาต้องลงเอยในช่องใดช่องหนึ่ง
   ไม่มีแถวไหนหายไปโดยไม่มีคำอธิบาย
3. **เทียบกับงบทดลอง ณ วันตัดยอด** — ยอดลูกหนี้และเจ้าหนี้รายใบรวมต้องเท่าบัญชีคุม
   ถ้าไม่เท่า จะบอกว่าต่างเท่าไหร่และให้ไปตรวจที่ไหน **ตั้งแต่ก่อนนำเข้า**

ลำดับขั้นสำหรับวันย้ายจริงอยู่ที่ [ใบตรวจวันย้ายข้อมูล](../../docs/19-migration-checklist.md)

## ตั้งค่า

| คีย์ | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|
| `clientId` / `clientSecret` | — | จาก MyCompany → connection |
| `baseUrl` | `https://openapi.flowaccount.com/v3-alpha` | ทดสอบก่อนด้วย `/sandbox` |
| `tokenUrl` | `https://openapi.flowaccount.com/token` | ถ้าได้ 404 ให้แก้ตามที่พอร์ทัลแจ้ง |
| `culture` | `th` | ส่วนของ path ที่ระบุภาษา |
| `pageSize` | `100` | ดึงทีละหน้าจนหมดโดยอัตโนมัติ |

โดนจำกัดอัตราหรือเซิร์ฟเวอร์ขัดข้อง (429 / 5xx) จะรอแล้วลองใหม่ถึง 5 ครั้ง
แบบถอยเป็นเท่าตัว ส่วน 4xx อื่นไม่ลองซ้ำ เพราะซ้ำไปก็ผิดเหมือนเดิม

⚠️ `config.json` มีความลับ อย่า commit — `.gitignore` กันไว้ให้แล้ว

## ทดสอบ

```bash
node tools/flowaccount-import/test.js     # 50 ข้อ ไม่ต่อเครือข่าย
```

ทดสอบตั้งแต่การแปลงฟิลด์ ไปจนถึงนำแฟ้มที่ได้เข้าระบบจริงในบริษัทเปล่า
แล้วตรวจว่ายอดคุมทั้ง 7 ข้อผ่านครบ และรับชำระต่อจากยอดยกมาได้โดยไม่นับซ้ำ
ข้อมูลตัวอย่างอยู่ใน `fixtures/` มีทั้งใบที่ปกติ ใบราคารวมภาษี
ใบที่ยอดบวกกันไม่ลงตัว และเลขผู้เสียภาษีที่ผิดหลักตรวจ
